# Power BI report: how to open it, how it is built, how it is checked

The report is a Power BI Project (PBIP), the text-based format Power BI Desktop opens
natively. It lives in `powerbi/report/` and is generated by
`src/build_powerbi_project.py` from the star schema CSVs and `measures.dax`.

**Status.** The project was opened in Power BI Desktop (September 2026 release), the
data was loaded, and every measure was evaluated by the Power BI engine and compared
with the SQL pipeline: 48 slicer combinations, 1,012 values, all within tolerance. The
result is in `docs/proof/powerbi_dax_check.txt`. Screenshots of the four pages taken
from Power BI Desktop are in `docs/img/powerbi_page*.png`.

## Files in this folder

| File | Role |
|---|---|
| `report/CardPortfolioTracker.pbip` | The report. Double-click to open in Power BI Desktop |
| `report/CardPortfolioTracker.SemanticModel/` | Model as TMDL: tables, relationships, 70 measures |
| `report/CardPortfolioTracker.Report/` | Report as PBIR: 4 pages, one JSON file per visual |
| `fact_customer_quarter.csv` | Fact. One row per scenario x customer x quarter on book |
| `dim_customer.csv`, `dim_tier.csv`, `dim_tenure.csv`, `dim_scenario.csv` | Dimensions |
| `dim_bridge_step.csv` | Helper for the waterfall axis. Not related to any table |
| `measures.dax` | Every measure, commented. The generator reads this file |
| `theme.json` | Colours and fonts that match `docs/index.html` |
| `expected_values.csv` | Pipeline results for all 48 slicer combinations. Not loaded into the model |
| `verify_dax.ps1` | Compares the measures in the open report with `expected_values.csv` |

The fact table holds base-case (linear assumption) values only. Off-book rows are not
stored: in scenario B an attrited customer has a Q1 row and no Q4 row.

## Open the report

1. Install Power BI Desktop (free): `winget install Microsoft.PowerBI`.
2. Run the pipeline once (`.\run_all.ps1`). This exports the CSVs and regenerates the
   project with the `DataFolder` parameter pointing at this folder on your machine.
3. Double-click `report\CardPortfolioTracker.pbip`.
4. Click **Refresh** on the Home ribbon. A project stores no data, so the first open
   shows a "Refresh now" banner. The CSVs load in a few seconds.
5. To hand someone a single file, use File > Save as and choose Power BI file (`.pbix`).

If the CSVs are somewhere else, change the parameter under Transform data > Edit
parameters > `DataFolder`.

## Check the report against the pipeline

With the report open in Power BI Desktop:

```powershell
.\powerbi\verify_dax.ps1            # add -Refresh to reload the CSVs first
```

Power BI Desktop runs a local Analysis Services engine while a report is open. The
script connects to it, evaluates the measures for every scenario x tier x tenure
combination, and compares them with `expected_values.csv`. It also checks that the four
effects add up, that the waterfall total equals Q4 spend, that the cohort view adds up,
that the sequential fallback is used where a factor is zero, and that spend does not
double when no single scenario is selected.

## Data model

Star schema, four many-to-one relationships, single direction (dimension filters fact):

| From (many) | To (one) |
|---|---|
| fact_customer_quarter[customer_id] | dim_customer[customer_id] |
| fact_customer_quarter[tier_key] | dim_tier[tier_key] |
| fact_customer_quarter[tenure_key] | dim_tenure[tenure_key] |
| fact_customer_quarter[scenario_key] | dim_scenario[scenario_key] |

`dim_bridge_step` and `_Measures` have no relationships. `dim_bridge_step` is one table
more than a strict star needs: the waterfall needs a column for its axis, and the steps
of a bridge are not an attribute of any customer.

Sort-by columns: `card_tier` by `tier_key`, `tenure_band` by `tenure_key`,
`scenario_name` by `scenario_key`, `step` by `step_key`. Key columns and the raw fact
columns are hidden, so report authors use the measures.

Formats: large dollar amounts are shown in thousands with one decimal ($12,741.9K).
This keeps digit grouping the same on machines with different regional settings.
Ratios are percentages with one decimal, the active rate with two.

## Changing the report

Edit `measures.dax` or `src/build_powerbi_project.py`, then run
`python -m src.build_powerbi_project`. Changes made inside Power BI Desktop are saved
into the same project files and will be overwritten the next time the generator runs,
so move anything worth keeping into the generator.

## Known limits

- A `.pbix` file is not in the repository. It is a binary file with the data embedded.
  Save one from Power BI Desktop when you need to send the report to someone.
- The native waterfall draws the opening bar, Q1 spend, as an increase from zero, in
  the increase colour. The Plotly version in `docs/index.html` draws it as a total.
- The cohort waterfall on page 4 shows two cohort totals. The Plotly version splits
  the stayers' change into frequency and ticket.
- The colour and label of the heatmap come from measures, so the matrix has no colour
  legend. The text box under it explains the scale.
- Sensitivity to the quarterly assumption is not in the Power BI model. It is in
  `ASSUMPTIONS.md` and `docs/results.md`.
